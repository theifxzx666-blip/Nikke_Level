## 〇·负零点七、v3.5 更新点（2026-10-28 五轮）：洗练消耗模型整体重做 + 顶栏与信息窗收尾

### 1. 旧算法错在哪（这就是「反直觉」的根因）

旧口径：`期望总消耗 = 上锁一次性 + 每次重洗 × (1 / 一次性全命中率)`，
其中「达成」被定义成 **所有参与行在同一把里同时满足目标**。

三目标空盘会被算成 **579 颗** —— 因为「三条目标词条同一把同时出现」的概率只有 `1.5e-3`，倒数就是 650 次。
实际玩法不是这样：**洗出一条就锁一条、逐条推进**。同一个场景真实期望只有 **86 颗**，整整差一个量级。

### 2. 新模型（对齐 ChrisLu7899/NIKKE-Workshop）

| 项 | 取值 | 出处 |
| :--- | :--- | :--- |
| **词条位出词条概率** | 1 / 2 / 3 号位 = **100% / 50% / 30%** | `SLOT_PROBS` |
| **阶数权重** | 1~5 各 **12**、6~10 各 **7**、11~15 各 **1**（合计 100） | `TIER_PROBS` |
| **类型权重** | 优越 / 攻击 / 暴伤 / 防御 = **10**，其余 = **12** | `STAT_PROBS_BASE` |
| **同盘不重复** | 同一把里类型不重复，且不与已锁行的类型重复（**不放回抽样**） | `engine.js` |
| **每次重洗** | **锁定条数 + 1** 颗 | `rerollStoneCost` |
| **上锁一次性** | 锁第 a 条付 `a+1` 颗 ⇒ 锁 1 / 2 / 3 条累计 **2 / 5 / 9** 颗，解锁不退 | `lockTransitionCost` |

求解方式是**精确动态规划**（状态 = 「哪个词条位锁着哪个目标」+「已达标集合」，≤ 34 个状态），不是蒙特卡洛估。
两阶段路线（先洗词条再洗数值）也在同一个 DP 里取更省的那条。

### 3. 国服 / 国际服是两套规则，结果差 5%~8%

| 规则 | 行为 | 例：盘上攻击 T12 → 目标 T15 |
| :--- | :--- | :-: |
| **国服 · 旧规则**（`cn`） | 洗数值直接覆盖，**可能抽出与当前完全相同的档位** | **102 颗** |
| **国际服 · 新规则**（`global`） | 把与当前完全相同的档位**排除后重新归一**，可保留原结果 | **93 颗** |

闭式解：`q̄ = (100·Σok − Σ_ok w²) / (100² − Σ w²)`。
例：T5 → T10 国服 `12/100` ⇒ **8.33 次**；国际服 `(100·12 − 144)/(10000 − 1150)` ⇒ **7.88 次**。

### 4. 三条路线，实测「自动」最省

同一场景（目标攻击 T15，盘上已有攻击 T12 + 优越 T10 + 装弹 T7）：

| 路线 | 国服 | 国际服 |
| :--- | :-: | :-: |
| **自动：先洗词条 → 再洗数值** | 102 颗 | 93 颗 |
| 只洗词条（变更效果） | 548 颗 | 548 颗 |
| 只洗数值（重置属性） | — | 91 颗 |

「只洗词条」最贵：类型和档位要同一把抽到位（`1 × 0.1 × 0.01`）。词条已经在盘上时，洗数值才是正解 ——
工具会在目标词条**不在盘面**时直接提示「先用自动/只洗词条把它洗出来」，而不是给一个误导性的数字。

## 〇·负零点六、v3.4 更新点（2026-10-28 四轮）：roster 补录 Persona 联动三骑

**起因**：从阿卡导入时提示「25 个角色已回填（响应 27 条）· 站点角色表缺 QUEEN（真）、雪子」。

**根因**：`roster` 由 **149 版**静态包生成，Persona 联动三骑晚于该版本，表里没有它们。
站点又把 `rid` 当主键（收藏、已记录、逐角色装备存档全挂 rid），所以缺条目不只是搜不到 ——
按名字匹配失败后，整个角色会被计入「缺」并跳过回填。

| rid | 角色 | 稀有度 | 企业/职业 | 强化表 | 武器 | 补录来源 |
| :-: | :--- | :-: | :--- | :-: | :--- | :--- |
| **870** | QUEEN（真） | SSR | 反常 / 火力 | 5104 | SG 霰弹 | `CharacterTable.Id 587001` |
| **871** | 雪子 | SSR | 反常 / 火力 | 5106 | MG 机枪 | `CharacterTable.Id 587101` |
| **872** | 埃癸斯 | SR | 反常 / 辅助 | 3303 | SMG 冲锋枪 | `CharacterTable.Id 587201` |

**做法（不手改 bundle）**

1. `data/roster_extra.json` 存补录项（含 `source` 表名与 `fieldRules` 字段推导规则）；
2. `scripts/apply_roster_extra.py` 合并进 `data.bundle.js`，**写之前先校验**：
   - `enh` 必须有属性曲线与强化系数（`curves` / `enhance` 里能找到）；
   - `gc` 里每个 GradeCore id 必须存在，且档数与该稀有度对应（SSR 11 / SR 3 / R 1）；
   - `coll.R` / `coll.SR` 必须等于 `favorites[稀有度][weapon].id`（`panel.js` 就是按 weapon 取收藏品表）；
   - 已存在且内容不同 → **拒绝覆盖**，报错让人工核对。
3. 幂等：bundle 重新生成后重跑一次即可补回，不会重复插入。

**字段是怎么定下来的**（都能复核，不是估的）

- `rid` = `CharacterTable.Resource_id`，稀有度/强化表/GradeCore 起始 id/暴击率全部直取该表；
- `weapon` = `CharacterShotTable[Shot_id].Weapon_type` —— 先用 **196 个存量角色 196/196 全中** 验证了这套编号与 roster 同源，再套到新角色；
- 中文名来自 `Locale_Character.lss`（`870_name` = QUEEN（真） / `871_name` = 雪子 / `872_name` = 埃癸斯）；
- 收藏品 `R/SR` id 与 `weapon` 的对应关系来自 `favorites`（1→1001xx / 2→1003xx / 3→1006xx / 4→1002xx / 5→1004xx / 9→1005xx），脚本会自检。

**结果**

- 角色池 **196 → 199**（R 9 / SR 20 / SSR 170）；
- 导入报告从「25 个角色已回填 / 缺 2」变成 **「27 个角色已回填 / 缺 0」**；
- **阶数自检仍 27/27**（`statTotalValue` 那条独立校验没被影响，说明词条口径没动）。

**验证**：`06-练度导出/verify_roster_extra.js` **17/17**（无头 Chrome：搜 `queen` / `雪子` / `xuezi` / `ags` / `真` 都能命中、选中后出面板、用真实响应跑映射 27/27 且 missing 为空）；
`verify_pinkuro.js` **32/32**（新增三骑的 rid / 字段齐全 / 推导非 0）。

**注意**：三个新角色的 `py` / `ini` 是手填的（静态表只有中文名，站点拼音表来自另一条构建链）——
`QUEEN（真）` → `queenzhen` / `queen`，`雪子` → `xuezi` / `xz`，`埃癸斯` → `aiguisi` / `ags`。

### 2. 为什么必须有转发层（用户不需要知道，但必须存在）

远端接口 `pinkuro.top:9984` 的跨域预检（`OPTIONS`）返回 **204 且不带任何 `Access-Control-Allow-*`**，
真实响应同样一个都没有（2026-10-28 实测）；而请求必须带自定义头 `X-API-KEY`，且 `?key=` 传参无效
（服务端明确回 `Required header 'X-API-KEY' is not present`）。

结论：**浏览器直连必被拦，任何前端写法都绕不过**——CORS 是浏览器自己执行的策略，不是服务端的善意。
所以必须有一台公网机器替浏览器去请求。这一层已经做好了，**普通用户完全看不到**：

| 项 | 值 |
| :--- | :--- |
| 中转地址 | `https://nikke-lv-relay.netlify.app/api/relay` |
| 写在哪 | `js/app.js` 的 `PRELAY_DEFAULT`（一处常量） |
| 用户看到什么 | 顶栏 **`阿卡 [Key] 👁 ✓ × ⟳导入`** 一组；「中转地址」那一行会自动隐藏 |
| 覆盖方式 | 网址后加 `?relay=http://127.0.0.1:8785`（本机开发），或填「中转地址」行（会重新出现） |

平台选型（都是实测，不是拍脑袋）：

| 平台 | 结论 | 原因 |
| :--- | :--- | :--- |
| **Netlify** | ✅ 采用 | 函数跑在 AWS Lambda，出站不限端口；`*.netlify.app` 本机直连可达 |
| Vercel | ⚠️ 备用 | 函数可用（`relay/` 目录里那份），但 `*.vercel.app` 实测直连超时，国内用户大概率打不开 |
| Cloudflare Workers | ❌ 不可用 | 部署后**忽略自定义端口**，`:9984` 被改写成 `443`（该端口不通） |
| Deno Deploy | ❌ 不推荐 | 2026-10-09 被 Cloudflare 收购，公告 2027-04 关停 |
| 公共 CORS 代理 | ❌ 禁用 | Key 会明文经过第三方，且随时失效 |

中转行为约定：只放行你的站点来源（`theifxzx666-blip.github.io` 与本机调试端口）、
只读 Key 不记录、只允许 GET、20 秒超时、响应 `no-store`。服务端代码在 `relay-netlify/`。

## 〇、v3.0 更新点

1. **角色检索：从「两段式」改成「一个框搞定」**（用户原话：「现在是先打关键词再选择，我的意思是直接整合」）。
   原先要给「筛选框 + 下拉」两个控件、还要先把关键词打进去才能选，很别扭。现在只有一个输入框：
   - **聚焦 / 点一下**就展开**全部 199 名**候选（按企业分组，`★ 收藏` 组置顶），**点一下就是选中**。
   - **输入即筛**，支持 **汉字子串**（`拉毗小红帽`）、**空格分词 AND**（`爱丽丝 仙境`）、
     **全拼**（如 `labi` —— 即「拉毗」的圈内别名读法）、**首字母缩写**（`lbxhm`）、**大小写不敏感**（`2b` / `D`）。
   - **命中处 `<mark>` 高亮**；**↑↓ 移动、Enter 选中、Esc 关闭**。
   - **★ 收藏**（点星标只切收藏、不改变当前角色）+ **范围开关**（`全部` / `★ 收藏` / `已记录`），
     不用再在一堆角色里翻自己常练的那几个。
   - 名字里有**全角冒号**（`拉毗：小红帽`）的 44 名角色，以前打 `拉毗小红帽` 或 `拉毗:小红帽` 都是 **0 条**，现在全部能搜到。
   - 「拉毗」按标准音是 `lapi`，但圈内习惯读「拉比」——**别名拼音**也一并支持，`labi` / `lb` 都能命中。
2. **改档位预览排版**（A 方案）：原先 5 列表格在窄左栏里会**裁掉「战力」列**，阅读体验差。
   现在改成**双行横条**：第一行 `等级 + 当前徽标 + 战力 + 较当前 +N`，第二行 `攻 / 生 / 防` 三围；
   当前档高亮描边，其余档给出**「较当前 +N」**，一眼看清每一档值多少。
3. **洗练模拟改成「目标驱动」**（对齐游戏里的实际操作）：老版本是「选池 + 选阶数区间 + 勾参与位」，
   用户原话「正常是选装备，选择要的词条和词条的阶数」。现在流程是：
   **① 选部位 → ② 选操作类型 → ③ 给参与重洗的行设「目标词条 + 目标阶数」→ ④ 出结果**。
   - **两种操作类型**：**`换词条`**（Change Effects，类型会变）与 **`只洗数值`**（Reset Attributes，类型不变、只重掷阶数）。
     切模式后结果会变（`只洗数值` 时类型下拉自动禁用）。
   - **参与重洗** = 勾选；**没勾的行视为锁定保留**，锁定都要按游戏实际**额外付费**。
   - 输出：**达成概率 / 期望洗练次数 / 期望总消耗**（外加原有的分布直方图与分位）。
4. **定制模组消耗口径按游戏实际重算**（用户原话：「现在明显对不上」）。旧版只算了「每次重洗」，
   **漏了「上锁」这个一次性成本**，而且概率口径也错了。现按 nikke.gg 等四源一致口径：
   - **重洗一次 = 锁定条数 + 1 颗**；
   - **「点锁定」本身也要付费**，同样是「锁到 N 条 = N+1 颗」，**解锁不退钱** →
     锁 1 条 `2` 颗 / 锁 2 条 `2+3=5` 颗 / 锁 3 条 `2+3+4=9` 颗（**一次性**）。
   - **期望总消耗 = 上锁一次性 + 每次重洗 × 期望次数（1/p）**。
   - **达成概率 p 的口径**改为「**目标行的词条类型命中 且 该行阶数 ≥ 目标阶数**」（洗得更高也算成），
     不再用「优于现状」——在没录装备时后者恒为 100%，期望消耗被算成 1 颗，明显失真。
5. **修掉「点一下词条数值，模拟就整体乱跳」**（用户报的 bug）。根因是内核用无种子的 `Math.random()`，
   且任何改动都会重跑抽样。现在：
   - 抽样改用**确定性伪随机**（`mulberry32`，种子 = 本次模拟输入的稳定哈希）；
   - 种子只由「**本次模拟的随机部分**」决定（角色 / 部位 / 模式 / 参与行 / 目标 / 现状 / 次数），
     **不含**面板与其它部位 → 改别的地方时本部位的**分布形状保持不变、只整体平移**；
   - 另加「输入指纹缓存」，输入没变就不重跑 5000 次抽样。
   - **同一输入必得同一结果**（已用「连续两次调用输出完全一致」锁死）。
6. **概率模型改成数据驱动**：内核接受 `typeWeights`（类型权重）与 `levelTable`（**长度 15 的逐阶权重表**）。
   现用社区实测口径占位：
   - 类型权重 —— 优越代码伤害 / 攻击力 / 暴击伤害 / 防御力 = **10**，其余五项 = **12**（即 10/100 与 12/100）；
   - 阶数 —— `1~5 阶 60% / 6~10 阶 35% / 11~15 阶 5%`，**段内暂按平均**（`12/12/12/12/12, 7×5, 1×5`）。
   - ⚠ 这两张表**是社区实测、非官方**，页面也照实标注；拿到拆包真值**只需换数组，代码与 UI 都不动**。

## 二、当前装备（装备等级 + 词条）与洗练

**流程：选好角色 → ① 填「装备等级」+ 录入「当前装备词条」并保存 → ② 在洗练区设目标、看战力变化 → 满意则覆盖保存。**

1. **① 当前装备**（中栏上块）：每个部位卡头部先选 **`装备等级`**（强化 0 ~ 5，T9/T10 上限 5），
   下面 4 部位 × 3 条逐条选**词条类型 + 阶数**。点 **「保存当前装备」** 落盘；
   标题右侧标签实时显示 `未录入 / 未保存 / 已保存`。
   整套装备（**等级 + 词条**）**按角色分别保存** —— 换角色会自动切到那个角色自己的装备（没录过就是空白、等级默认满级 5）。
   改**装备等级**会立即重推面板三围与战力（每级 +10% 装备基础属性）。
   > **同一件装备不会出现重复词条**：本部位已被其它行选走的类型会自动**置灰**；把某行改掉后置灰立即释放。
2. **② 装备词条洗练**（中栏下块）：左列是①里已保存的**当前装备**（只读参照），右列选**洗练目标**；
   改动右侧即实时刷新右栏（战力变化 / 部位归因 / 逐条明细）。
   点 **「洗练目标 ← 当前装备」** 可把当前装备整份复制到目标再微调。
   这里**不做去重限制** —— 洗练时词条位置可能被打乱，重复类型是允许的。
3. 洗练结果满意时，点 **「确认洗练 → 覆盖当前装备」**：把目标固化为当前装备并保存（练度 + 整套装备词条一并落盘）。

### 洗练模拟（按部位 · 目标驱动 · v3.5 重做）

右栏那块「洗练模拟」用来回答「**给这件装备洗词条，大概能洗成什么样、要花多少模组**」。
交互顺序：**① 选部位 → ② 选操作 → ③ 选服务器规则 → ④ 给这个部位设 1~3 条目标词条 → ⑤ 出结果**。

| 输入 | 说明 |
| :--- | :--- |
| **部位** | 头部 / 衣服 / 手部 / 鞋子（默认头部） |
| **操作** | **`自动`**（先洗词条拿到名字 → 再洗数值拉档位，**实测最省**，默认）／**`只洗词条`**（变更效果：类型和档位要同一把抽到位）／**`只洗数值`**（重置属性：类型不变，只重抽档位） |
| **服务器规则** | **`国服 · 旧规则`**（结果直接覆盖，可能抽出与当前完全相同的档位）／**`国际服 · 新规则`**（排除与当前完全相同的档位后重新归一，**洗数值更快**） |
| **目标（3 行）** | 每行 = `目标词条类型` + `最低档数（≥ 口径）`。类型选「— 不设 —」就表示这条不参与；同部位其它行已选走的类型自动**置灰**。<br>新设一条目标时最低档数默认 **T10** |
| **模拟次数** | 蒙特卡洛抽样次数（默认 4000，只影响「洗一次会变成什么样」的分布，不影响消耗计算） |

输出：**当前整套战力** / **该部位现状（内部战力 + 三条词条）** /
**洗后最低·最高** / **洗后 P10·P50·P90** / **洗后平均** / **平均变化** / **变化分位** / **直方图**，
以及**洗到目标要多少石头**。

> **不再有「☑ 参与重洗 / 锁定几条」这套输入**（v3.5 删掉）：锁定条数由模型自己推 ——
> 打到目标的会自动锁上，跟你实际做法一致，不需要用户先声明。

### 洗到目标要多少石头（v3.5 重做）

| 字段 | 含义与算法 |
| :--- | :--- |
| **目标 / 已达成** | 设了几条目标、其中几条当前已满足；右侧标出用的是国服还是国际服规则 |
| **每次重洗消耗** | **锁定条数 + 1 颗**：不锁 `1` / 锁 1 条 `2` / 锁 2 条 `3` / 锁 3 条 `4` 颗 |
| **洗一次就命中的概率** | 按当前所处阶段给：名字还没齐 → 这一把洗出新名字的概率；名字都齐了 → 洗数值时至少一条达标的概率（`Π q`） |
| **路线拆分** | `自动`：`词条阶段 X 颗 → 数值阶段 Y 颗`；`只洗词条 / 只洗数值`：`重洗 X 颗（≈ N 次）+ 上锁 Y 颗` |
| **期望总消耗** | 精确 DP 求出的期望值（**不是** `上锁 + 每次重洗 × 1/p` 那种估算） |

> 上锁是一次性付费且**解锁不退**：锁第 a 条付 `a+1` 颗 ⇒ 锁 1 / 2 / 3 条累计 **2 / 5 / 9** 颗。
> 目标词条**不在这个部位的盘面上**时，`只洗数值` 会给明确提示（「先用自动/只洗词条把它洗出来」），
> 不会输出一个看起来合理但根本达不到的数字。

### 概率模型（v3.5 起在 `js/reroll.js`，数据驱动）

概率与费用模型**独立成一个文件**（`js/reroll.js`，不碰 DOM，可在 Node 里单测），口径逐条对齐
开源实现 **ChrisLu7899/NIKKE-Workshop**：

| 维度 | 取值 |
| :--- | :--- |
| **词条位出词条** | 1 号位 **100%** / 2 号位 **50%** / 3 号位 **30%**（`SLOT_APPEAR`） |
| **阶数权重** | `1~5 阶` 各 **12**、`6~10 阶` 各 **7**、`11~15 阶` 各 **1**（合计 100，`TIER_WEIGHT`） |
| **类型权重** | 优越代码伤害 / 攻击力 / 暴击伤害 / 防御力 = **10**；命中率 / 最大装弹数 / 蓄力伤害 / 蓄力时间 / 暴击率 = **12** |
| **同盘不重复** | 同一把重洗里类型不重复，且不与已锁行的类型重复（不放回抽样） |
| **洗数值（重置属性）** | 只重抽目标词条的档位，类型不变 |
| **国服 / 国际服** | 旧规则直接覆盖；新规则排除与当前完全相同的档位后重新归一 |

- 求解用**精确 DP**：状态 = 「哪个词条位锁着哪个目标」+「已达标集合」（≤ 34 个状态），结果就是期望值本身，不是抽样估。
- 「先洗词条再洗数值」两阶段路线在同一个 DP 里跟「直接洗数值」比大小，取更省的那条 —— 这也是「自动」比单一路线便宜的原因。
- 洗数值的长期命中率有闭式解：`q̄ = (100·Σok − Σ_ok w²) / (100² − Σ w²)`（新规则）；
  旧规则就是 `Σok / 100`。例：T5 → T10 国服 **8.33 次**、国际服 **7.88 次**。
- 抽样（「洗一次会变成什么样」）用**确定性伪随机**（种子 = 本次模拟输入的稳定哈希）：**同一输入必得同一结果**；
  改别的部位 / 改面板时，本部位的分布**形状不变、只整体平移**。
- 拿到拆包真值后只需改 `reroll.js` 顶部的三张常量表，代码与 UI 都不用动。

## 三、公式与数据来源（全部实证）

```
面板 = Group1 + Group2
Group1 = (等级基础 × 星级 + 循环室 + 好感度) × (1 + 核心×0.02)
Group2 = 装备 + 魔方 + 收藏品
```

## 四、已知边界（明确标注，不猜）

1. **装备同厂加成**（`EquipCorporationStatBonus = 0.3`）：`WithCorpBonus()` 类文件不在反编译产物内，
   参考站口径为**不加成**（已用 13/13 打点证明）。客户端真实行为**待验证**——
   v3.2 起按反馈**移除界面开关**，内部固定不加成；`panel.js` 里的 0.3 分支保留，日后验证完可直接接回。
2. **过载词条的出现概率**：静态表不含概率。模拟器的**阶数分布（默认 1~15 均匀）与类型概率（池内等概率）都是假设**，
   不是游戏实测掉落/洗练概率，界面已标注；结果只用于比较相对高低。
3. **优越代码伤害口径**：本工具按客户端逐阶 `FunctionBattlepower` 精确计算（1 阶 +762）；参考站压成汇总口径（+761），差 ±1~5。
4. **静态数据版本**：当前用 **149 版**（152 版解密参数已变，未解）。新角色/新表可能缺失 ——
   v3.4 起用 **`data/roster_extra.json` + `scripts/apply_roster_extra.py`** 做增量补录（按 rid 幂等合并，
   不动 bundle 其余部分）。以后再遇到「导入时提示站点角色表缺 xxx」，把新角色的 4 个字段查出来补进 json 重跑一次即可。
5. **SSR 专属收藏品上限只有 2 级**（0~2），与普通收藏品（0~15）不同，界面按各自上限处理。
