## 三、基地等级 × 关卡进度的整合（你点名要方案的那个）

**问题**：两套输入都能得出基地等级，但用户只用其中一套 → 页面上两套并排 = 两个真相。

**方案：基地等级是唯一真值，关卡进度降级为「推算助手」**

```
当前基地（前哨站 · 以手填等级为准）                  ⓘ
  前哨基地防御等级  [ 518 ]        战术学院是否满级 [ 是 ]
  推荐直接手填……（现有文案保留）
  ▸ 关卡进度推算（可选，仅用于校验基地等级）      ← 折叠，默认收起
      普通 Chapter 48 ▾ / 未选择 ▾    困难 Chapter 48 ▾ / 未选择 ▾
      [采用推算值 lv.XXX]                       ← 只在推算值 ≠ 手填值时出现
```

三条硬规则：
1. **不收覆盖**：手填值永远优先，选关卡只更新「推算 lv.XXX」提示与那枚按钮。
2. **推导值不一致才提示**：一致时不打扰；不一致时文案写「推算 Lv.712，与手填 518 差 194 级，确认一下？」，避免用户误填。
3. **国服口径降噪**：推算说明里保留「国服约多 3 关，可能偏高」，但不做成红色警告 —— 它是辅助，不是错误。

实现上无需改 `app.js`：现有 `#btnAdoptBase` + `#baseHint` 机制已经就是这个行为，v2 只是把它折叠起来、位置挪到基地组内。

## 四、云端下发：schema 与控制台

### 4.1 用户端看到的（只读）

```
活动收益   2026-11-15.1        发布于 2026-11-15 04:00
LIE CAUSE RECOIL   28天大活动·地图  11-04 → 12-02   [计入中·剩 27 天]
NYA NYA PARADISE   21天大活动       10-14 → 11-03   [已结束]
活动参数由云端统一下发，页面只读。
```

### 4.2 建议的配置结构

```json
{
  "version": "2026-11-15.1",
  "published_at": "2026-11-15T04:00:00+08:00",
  "schema": 2,
  "defaults": {
    "wipeouts_per_day": 3, "wipeout_hours": 2, "reset_at": "04:00",
    "monthly_card_default": false, "cost_table": "builtin:step50"
  },
  "events": [
    { "id": "liecause_recoil", "name": "LIE CAUSE RECOIL", "template": "large28map",
      "start": "2026-11-04", "end": "2026-12-02", "enabled": true }
  ],
  "notes": "内置默认参数仅用于日志回显，不参与覆盖"
}
```

三条约束：
- **版本只增不改**：改配置 = 出新版本号，旧版本可回切（学 `rainbow_bridge`）。
- **用户端只读**：页面不写回，不接受"手动覆盖后静默生效"。
- **日志即契约**：页面上看不到的参数（重置时间、等价小时、升级消耗），必须在运行日志里能看到来源与值。

### 4.3 控制台（你额外要的那个）

同一套样式，左表单右 JSON：
- 左：活动列表（名称 / 开始 / 结束 / 删除 / 新增）
- 右：实时 JSON 预览（随输入变化）
- 顶：草稿 · 生效版本 vX · [发布]
- 发布 = 生成新快照 + 切生效指针；**不触碰任何用户本地数据**

| 配置版本与快照 | [yi-nology/rainbow_bridge](https://github.com/yi-nology/rainbow_bridge) | 编辑区与生效版本分开、锁版快照、任意版本差异对比 |
| 配置 schema 校验 | [imamabudaud/config-platform](https://github.com/imamabudaud/config-platform) | JSON schema 校验 + 灰度 rollout + 回滚 |
| 模板→表单 | [mindobix/local-shareanyjson](https://github.com/mindobix/local-shareanyjson) | 一份 template 同时驱动 JSON 与 UI 表单视图、版本历史 |

**采纳结论**：步骤条用 daisyUI 的三态语义（不引 UI 库，照样式自己写，与本项目"零依赖静态站"一致）；结果页用 hw-savings 的「总览 + Show breakdown」；控制台用 rainbow_bridge 的「编辑区 ≠ 生效版本」。
