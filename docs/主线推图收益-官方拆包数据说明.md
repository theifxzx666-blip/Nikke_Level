# 主线推图收益 · 官方拆包数据说明

> 用途：说明计算器「预计新主线推图收益」字段的数据来源、口径与落地方式。
> 对应提交：`9d5b907`（2026-10-12）｜数据文件：`nikke_src/data/stage_clear_resources.json`
> 生成方式：本文件由 `临时文件/scripts/_gen_doc_stage_clear.js` 从数据文件现算表格，**表格内容与上线数据必然一致**。

## 1. 为什么要改

改动前 `data/stage_clear_resources.json` **只有第 38 章一条**，来自「屯箱子计算器」的 37~38 章实测估算；界面上 6 个输入框的默认值也是写死的常量，且说明文案写着「暂无公开的章节通关收益统计表」。

本次改用**官方拆包逐章汇总**，覆盖官方收录的全部 47 章，并按所选章节自动带出。

### 只取三项资源

| 保留 | 说明 |

## 3. 键口径（最容易踩的一点）

```
计算器章节号 K  =  官方 ChapterId − 1  =  游戏内关卡前缀
```

即 `stage_map.json` 里的 `"Chapter K"` ↔ 关卡 `K-x` ↔ 官方第 `K+1` 章。

- 举例：键 `"37"` = 官方第 38 章「苦战」= 关卡 `37-1 … 37-36 BOSS`
- 生成脚本从官方 `关卡名` 前缀直接反推，并对全 47 章断言「该章所有关卡的 `关卡名` 前缀 == 章节号 − 1」→ **0 例外**

**覆盖范围**：官方 47 章 → 键 `0` ~ `46`。
进度下拉的末章（`Chapter 47` / `48`）**超出官方收录范围**，数据文件里没有；前端按 `fallback_chapter`（= `46`，即「新生」）带出，并在界面上**明示**：「第 48 章暂无官方拆包数据（已收录至第 46 章），暂按第 46 章「新生」带出。」

> 另注：进度下拉最低是 `Chapter 2`（`stage_map` 的 `normal_start_id = 19` 会过滤掉 Chapter 0/1 的关卡），所以键 `0`/`1` 目前只在数据文件里、界面上选不到。

## 4. 前端接入方式

| 位置 | 改动 |
|---|---|
| `js/app.js` · `buildSnapshot` | 计入范围 ≠ 不计算时：普通 → 困难（仅「普通+困难」）→ **主线任务三项**（与模式无关）依次累加；credit/battle **×1000** 换算为内部绝对量，dust 不换算 |
| `js/app.js` · `syncStageClearFromFuture` | 按 `f_future_normal_chapter` 取章；带出 9 个字段；图例与说明同步刷新 |
| `index.html` | 新增「主线任务信用点/战斗数据/红球」一行（`#stageTaskRow`，不计算时隐藏）；标签标注 `·K`；说明文案改为官方来源 |
| 数据文件 fetch | 补上 `?v=`，避免 Pages / 浏览器缓存旧数据 |

### 两个已修的历史缺陷（本次顺手）

1. **单位换算缺失**：推图数据的 credit/battle 存的是 K，而内部口径是**绝对值**（`bare_credit` 默认写 `66605K`、升级消耗表也在 `costForLevel` 里 `×1000`）→ 原代码**漏了 ×1000**，旧默认值 `25864` 实际只贡献 25,864（相对 66,605K 的现有量约等于没有）。
2. **章节联动只生效一次**：原判断是「当前值 == 初始默认值才自动带出」，一旦带出过别的章，第二次切章就不再更新。现改为记录**上次自动带出的值**，用户手动改过即不再覆盖（`stageAutoFilled`）；同时 `if (!n) return` 会让 `Chapter 0` 被跳过（已修）。

另加**旧口径存档迁移**：localStorage 里命中旧默认值（`25864 / 74096 / 630 / 2615 / 73446 / 1630`）的一律视为「未自定义」，改用新默认，避免老用户停留在旧数据。
