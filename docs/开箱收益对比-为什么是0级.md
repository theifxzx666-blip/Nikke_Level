> **一句话**：活动收益**已经**被正确计入（它给的小时箱确实存到了开放日才开，贡献「多升 18 级」里的 **9 级**）；
> 「开箱收益对比 0 级」衡量的是**另一件事** —— 同一批箱子早开 vs 晚开，因基地收益只高 1.96% 而差 0 级。
>
> 补充：**不是活动收益置入造成的**。这是 `box_gain_vs_now` 的口径本身决定的 ——
> 它只衡量「同一资源底盘下，箱子按**新基地收益**折算比按**当前基地收益**折算多升几级」，
> 收益差只有 1.96%，取整后就是 0 级。活动收益走的是另一条线（等待期），
> 在「多升 18 级」里贡献了 **9 级**。

## 2. 为什么 `box_gain_vs_now` = 0

代码（`js/scenarios.js` → `futureMainStoryScenario`）：

```js
var baseSnap = Object.assign({}, snapshot, { stage_clear_resources: C.zeroRes() });
var lvNew = immediateLevels(baseSnap, true, true, snapshot.future_income_per_hour).level;
var lvOld = immediateLevels(baseSnap, true, true, snapshot.income_per_hour).level;
boxGain = Math.max(0, lvNew - lvOld);
```

`immediateLevels` 里唯一与「收益」有关的是**箱子的折算**（`fixedBoxResources` 与自选箱 `mode:"hours"` 都按 `小时 × 收益` 计价）。
所以 `boxGain` 就是「箱子更值钱」这一件事的量化结果。

| | 现状基地 | 未来基地 |
|---|---|---|
| 基地等级（导出文件） | 571 | 589 |
| 收益 credit/h | 63,620 | 64,870 |
| battle/h | 643,570 | 657,790 |
| dust/h | 105.87 | 107.56 |
| 相对增幅 | — | **+1.96%** |

固定箱底折算资源随收益按同比例变化：

| 资源 | 现状收益下 | 未来收益下 | 增量 | 增幅 |
|---|---|---|---|---|
| credit | 153,578,680 | 156,596,180 | +3,017,500 | +1.96% |
| battle_data | 934,463,640 | 955,111,080 | +20,647,440 | +2.21% |
| core_dust | 381,890 | 389,136 | +7,246 | +1.90% |

**敏感度实测**（用真实引擎扫收益倍率，问「要涨多少才多升 1 级 = 到 555」）：

| 变化方式 | 需要涨幅 | 折算 |
|---|---|---|
| 三资源同涨 | **+2.50%** | credit ≥ 65,210/h（≈ 基地 592 级） |
| 只涨红球收益 | **+4.00%** | 红球 ≥ 110.1/h（≈ 基地 599 级），589 级只有 107.56 |
| 只涨战斗数据收益 | +8.00% | — |
| 只涨信用点收益 | +20.00% | — |

**为什么「多 2 个红球」也不够**：554 → 555 一级要 **credit 8,185,000 + battle 72,544,000 + core_dust 14,000**（三样都得给够）。
589 级相对 571 级的收益差把整个箱池抬高的量是 credit **+3,017,500** / battle **+20,647,440** / dust **+7,246** ——
红球多出的 7,246 个只有 14,000 的 **52%**，战斗也只到 8% 阈值里的 2.21%。
三资源联合约束下**每一项都差一点**，取整后就是 0 级。

> 换个说法：**「+0 级」不是「资源差为 0」，而是「差得不够升 1 级」**。要让它变成 +1，
> 未来基地等级得再往上抬约 3 级（571 → ~592 才够 +2.5%），或者未来收益手填得更高。

> 即：「+0 级」的准确含义是 **「开箱本身更值钱这件事没带来 1 级」**，
> 而不是「资源差为 0」。差异是有的（+3.0M credit / +20.6M battle / +7246 dust），只是不足以跨过 1 级的消耗门槛。

## 3. 那「多升 18 级」从哪来？活动收益贡献了多少

用真实 `scenarios.js` 逐项叠加，每一步都落在整数等级上：

| 步骤 | 等级 | 增量 |
|---|---|---|
| ① 现状全箱梭哈（现状裸资源 + 现状箱量，@571 收益） | 554 | — |
| ② ＋等待期自然积累（41 天基地收益 + 每日歼灭 6h） | 563 | **+9** |
| ③ ＋活动**直接资源**（credit 15.92M / battle 52.60M / dust 960） | 564 | **+1** |
| ④ ＋活动**箱**（挑战者成长宝箱 ×1515 + 方舟官方补给物资Ⅰ ×130） | 572 | **+8** |
| ⑤ ＋收益切到 589 级（= `boxGain` 的唯一通道） | 572 | **+0** |
| ⑥ ＋新主线推图收益（导出文件里仍是旧值 25,864 / 74,096 / 630） | 572 | +0 |
| 合计 | 572 | **+18** |

- **活动收益贡献 = ③ + ④ = 9 级，占这 18 级的一半**（直接资源 +1、活动箱 +8）
- 纯等待期自然积累 = 9 级
- 箱子收益差 = 0 级（本节 §2）
- 旧口径推图收益 = 0 级（25,864 相对 1.5 亿箱底可忽略）

**所以面板上「开箱收益对比 +0 级；另有等待期自然积累 18 级」是对的**：
18 级全来自等待期（自然 9 + 活动 9），箱子因收益提高而多出的部分确实是 0。

## 5. 活动收益给的小时箱：确实「存起来、开放日再开」（已正确实现）

`js/events.js` 的 `inject()` 把活动产出**按原形态**注入开放日快照，不折算、不提前消耗：

## 6. 两种「开箱收益对比」语义（待定）

| 口径 | 公式 | 本案例值 | 含义 |
|---|---|---|---|
| **现口径** `box_gain_vs_now` | 同底盘下，箱子按新旧收益折算之差 | **0 级** | 「箱子更值钱」这一个通道 |
| 替代口径 | (开放日梭哈 − 开放日裸) − (现状梭哈 − 现状裸)<br>= (572 − 533) − (554 − 524) | **9 级** | 「等待期多攒出来的箱子（含活动箱）」 |

- 现口径下 18 = **0**（箱子更值钱）+ 18（等待期积累）
- 替代口径下 18 = **9**（开箱）+ 9（等待期自然积累）—— 与 §3 分解的「活动贡献 9 级 / 自然 9 级」正好吻合，读数更符合直觉
